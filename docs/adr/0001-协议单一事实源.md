# ADR 0001：协议布局单一事实源——生成化，不合并两端 adapter

- 状态：Accepted
- 日期：2026-11-05
- 关联：ARCHITECTURE.md §4（三态接入模板）、§11（唯一验收标准）

## 背景

架构评审（2026-11-05）三方向侦察独立收敛到同一摩擦：协议 payload 布局知识手抄多处——
`draw_encoding.rs`（Rust 编码）→ `ocir-schema.generated.ts`（生成常量）→ `draw-ir.ts`
（TS 手写 decode）→ `dumpEncodedFrameOps`（debug dump 第三次手写）；gpu_stream 的
`webgl_api.js` 手写 [opcode][payload] 镜像。原先防漂移的 `write_ocir_schema` 测试随
全仓单测退役已不存在，根 `web/src/generated/` 死副本已实证漂移（少 opcode 54/55）。

## 决策

1. **布局知识生成化**：协议常量与 payload 字段布局的唯一事实源在 core
   （`ir/draw_encoding.rs` / `ir/gpu_stream.rs` / `ir/schema_gen.rs`）；TS 侧一切
   布局知识由 `ocir-schema-gen` bin 生成。
2. **构建期自动重生成，不做检查**：bin 接为 `crates/opencat-web/web/package.json`
   build 链第一步，每次构建前无条件重写生成文件。漂移在构造上不可能，而非靠测试抓。
   不新增任何单测 / CI 检查项（2026-11-05 用户拍板：唯一测试 = 三例 k3diff 渲染门）。
3. **两端重放 adapter 不合并**：engine（tiny-skia）与 web（canvaskit.wasm）消费同一
   OCIR 协议是宪法 §4 设计意图——web 重放端天然是 engine 实现的对拍 oracle。
   本 ADR 明确禁止未来评审再把"合并两端解释器"当深化候选；摩擦只允许在
   "布局知识未生成化"上，不允许用"统一实现"解。

## 后果

- 改一个 op 的动作收敛为：改 core 表 → 生成面自动刷新两端。
- `draw-ir.ts` 拆层后 decode 是唯一读字节处，dump 吃 `DecodedFrame` 不再啃字节。
- web 构建链依赖 cargo（`cargo run -p opencat-core --bin ocir-schema-gen`）。
